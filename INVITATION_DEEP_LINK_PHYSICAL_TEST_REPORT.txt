1. EXACT ROOT CAUSE
   NOT a code defect. The complete link chain was audited file-by-file
   (src/invitationLinks.ts, public/invite/index.html, the deployed
   github-pages-hosting copy, app.json, src/invitationDeepLink.ts,
   App.tsx) and found syntactically correct and internally consistent
   throughout -- one canonical format, agreed everywhere.

   The test iPhone has never had a real Lilica build installed -- no
   EAS build (development or production) has ever been created for
   this project (a standing, previously-documented fact). The
   invitation link was therefore opened inside Expo Go, and Expo Go
   CANNOT and does not register a third-party app's own custom URL
   scheme (lilica://) with iOS -- this is a fundamental Expo Go
   limitation, not a Lilica misconfiguration. iOS's "Safari cannot open
   the page because the address is invalid" is its standard, generic
   message for ANY custom scheme with no registered handler on the
   device -- confirmed, by direct inspection, that the URL itself was
   NOT malformed.
