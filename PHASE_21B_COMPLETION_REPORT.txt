7. SEARCH INTERACTION - REQUIRED BEHAVIOUR
================================================================

The Home search box is NOT an inline expanding search field.

When the user taps/highlights the Home search control:

Home
→ Search [FirstName]

Example:

Home
→ Search Maggie

The app should navigate to the existing dedicated Search screen.

This is the interaction already physically tested and approved.


================================================================
8. SEARCH SCREEN - REQUIRED STATE
================================================================

When the dedicated Search screen opens:

- title should be:
  Search Maggie
  using the current supported person's first name;

- the search field should immediately receive focus;

- the device keyboard should open automatically;

- the user can immediately begin typing;

- search results should populate beneath the field as they type;

- no second tap should be required to activate the field.

Preserve the existing Phase 20 unified-search logic.

Do NOT rebuild Search.


================================================================
9. SEARCH SCREEN COPY
================================================================

Retain the current simple supported-person-specific copy.

Example:

Search Maggie

Search appointments, tasks, documents...

Search for anything already saved for Maggie - an appointment, a task,
a document, a contact.

Keep this dynamic based on the current supported person.

Do not hard-code Maggie.


================================================================
10. SEARCH BACK NAVIGATION
================================================================

The back navigation on Search has one clear job:

Search Maggie
→ Back
→ Home

When the user presses the top-left back button:

- return directly to Home;
- do not route through onboarding;
- do not route through setup;
- do not change tab;
- do not change supported person;
- do not open an intermediate screen.

The user should feel they temporarily entered Search from Home and then
returned to Home.

Preserve the currently selected supported person.


================================================================
11. SEARCH EXIT STATE
================================================================

On returning to Home:

- Home should still show the same supported person;
- the Home state should remain coherent;
- no stale search results should remain visible;
- the app should not reset unrelated Home state.

Do not create a navigation stack regression.


================================================================
12. HORIZONTAL DASHBOARD STRIP
================================================================

The horizontal dashboard card strip must remain horizontally scrollable.

The cards currently represent the Home summary/dashboard information.

Do not replace these cards with another concept.


================================================================
13. ADD ACTIVE LEFT / RIGHT CHEVRONS
================================================================

A usability problem remains:

it is not sufficiently obvious that the dashboard card strip is horizontally
scrollable.

Add a clear but restrained ACTIVE CHEVRON on BOTH sides of the horizontal
strip.

Visually:

<   [ cards / horizontally scrollable content ]   >

The chevrons should make it obvious that more content can be explored.


================================================================
14. CHEVRON BEHAVIOUR
================================================================

The chevrons must not be decorative only.

They must be interactive.

LEFT CHEVRON:
- scrolls the horizontal strip left by a sensible amount.

RIGHT CHEVRON:
- scrolls the horizontal strip right by a sensible amount.

Use smooth scrolling where supported.

Do not jump unpredictably.


================================================================
15. CHEVRON ENABLE / DISABLE STATE
================================================================

The chevrons should reflect whether further scrolling is possible.

At the left-most position:

- left chevron should appear disabled/subdued;
- right chevron remains active if more content exists.

At the right-most position:

- right chevron becomes disabled/subdued;
- left chevron remains active.

In the middle:

- both may be active.

Do not show an apparently active chevron that does nothing.


================================================================
16. SWIPE MUST STILL WORK
================================================================

The user must still be able to swipe/drag the horizontal strip naturally.

Chevrons are an additional discoverability/navigation aid.

They must NOT replace touch scrolling.


================================================================
17. CHEVRON VISUAL STYLE
================================================================

Use the existing Lilica visual language.

Chevrons should be:

- restrained;
- obvious enough to notice;
- premium;
- not giant;
- not floating blue developer controls;
- not visually dominant over the cards.

They may sit just outside or slightly overlap the strip edges if that best
matches the approved design.

Use existing colours/theme tokens where possible.


================================================================
18. CHEVRON ACCESSIBILITY
================================================================

Add appropriate accessibility labels/roles.

Examples:

Scroll dashboard right

Disabled state must be conveyed correctly.


================================================================
19. CARD STRIP LAYOUT

Do not make cards tiny just to eliminate scrolling.
