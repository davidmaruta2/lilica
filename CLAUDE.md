**Phase 18 (Privacy, Settings, Export & Account Lifecycle) is implemented, validated, committed and pushed (`e3dc819`).** A new "Privacy & data" Settings entry provides: real display-name editing (reusing `AuthProvider`'s existing `saveProfile`, not a second write path); a real data-export RPC (`export_my_data()`, domain-filtered through the same `membership_has_domain_access()` every other read uses) written to a local file and shared via the OS share sheet, never stored server-side; "Clear data from this device" (warns about anything genuinely pending first, then signs out so the next sign-in rebuilds cleanly from the cloud); "Leave [care space]" for non-organiser roles, wiring Phase 15's previously-unused `leave_care_space()` RPC into real UI for the first time; and a "Delete account" entry that runs a real, read-only precheck (`account_deletion_precheck()`) but is explicit that deletion itself isn't available yet. **This last point is a genuine, investigated architectural finding, not a shortcut**: `care_space_memberships.user_id references auth.users(id) on delete restrict`, and membership rows are themselves permanently `on delete restrict`-referenced from records/occurrences/assignments/links/attachments by deliberate design (historical attribution) — so `auth.users` cannot be deleted today without either an FK violation or destroying shared care-space history, and real account deletion needs its own, separately-approved schema change. Closed a real Phase 17-acknowledged gap along the way: document delete/link/attachment cleanup now goes through a durable AsyncStorage-backed retry queue (`src/documentCleanupQueue.ts`), surviving an app kill mid-cleanup, rather than Phase 17's best-effort fire-and-forget.
