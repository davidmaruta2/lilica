Home projection, unified To Do, cleaner Calendar, universal Add, document
relationships/follow-up, modern People/Care Circle experience, a real

6. GENUINE GAPS
Recent Activity/care history, Search, Medication structure (bounded/
non-clinical), Contingency/emergency information, Calendar device sync/
export, contextual record comments (a narrow slice distinct from
messaging), Contact importing, collaboration notifications (distinct from
personal reminders), Supported-person optional profile fields, member
management/filtering refinements, export narrative/handover readability.
Full detail in docs/PHASE_20_GAP_AUDIT.md sections 6-22.

7. DELIBERATE OMISSIONS
General group messaging/chat; a generic parallel Notes feature; connected
health-device integration; copying Jointly's own flat module-drawer
navigation. Full reasoning: docs/PHASE_20_GAP_AUDIT.md section 7.

8. UNCERTAIN/RESEARCH-REQUIRED AREAS
DST-recurrence technical parity (a small self-check, not a product
decision); Jointly's exact Contingency Plan export content; whether Jointly
has a dedicated keyword search distinct from confirmed member/type
filtering; exact scope boundary for contextual record comments; legal/
privacy research needed before medication/health/emergency-information
work. Full list: docs/PHASE_20_GAP_AUDIT.md section 8.

9. RECENT ACTIVITY ASSESSMENT
Assessed as the single most carer-relevant genuine gap found, independently
corroborated by the one-year-user, family-handover and six-person-
collaboration tests rather than only the competitor comparison. Existing
per-record timestamp/confirmation data provides a foundation; no
cross-record aggregation or UI exists today. Full detail: section 9.

10. SEARCH ASSESSMENT
No search of any kind exists; severity grows materially over a user's first
year. A scoped per-section text filter (Documents/Bills/Contacts) is
recommended as the lower-risk, likely-sufficient version over a full global
search index. Full detail: section 10.

11. MEDICATION ASSESSMENT
Current careNote folding is insufficient for schedule/dose/administration
tracking, but the brief explicitly warns against a clinical system without
a safety/liability analysis this audit cannot perform. A bounded,
non-clinical "what/dose/schedule as reference information" slice is
identified, gated on legal/privacy classification before any commitment.
Full detail: section 11.

12. CONTINGENCY/EMERGENCY ASSESSMENT
No single place answers "what does someone else need to know if I'm
unavailable" today. A curated summary VIEW built from already-existing data
(not a new record type or new data collection) is the bounded, low-schema-
impact recommendation. Full detail: section 12.

13. CALENDAR INTEGRATION ASSESSMENT
No device-calendar sync/export exists. Two-way sync risks real duplication;
a one-way, read-only export/subscription feed is recommended as materially
lower-risk. Full detail: section 13.

14. NOTES ASSESSMENT
Existing careNote + per-record notes + attachments already adequately
cover the general unstructured-information need; a generic parallel Notes
feature is not justified. Full detail: section 14.

15. MESSAGING ASSESSMENT
General chat is a deliberate omission (duplicates WhatsApp/iMessage/SMS,
risks the module-drawer anti-pattern). A narrower "contextual comment on a
record" need is genuinely different and identified as a small, bounded
candidate requiring explicit product-owner scope judgement to avoid
scope-creep into general chat. Full detail: section 15.

16. CONTACT-IMPORT ASSESSMENT
Genuine convenience win for Key Contacts; costs a new expo-contacts
dependency and a new device permission; recommend a one-time
import/copy, never a live sync. Low-medium complexity, low regression
risk. Full detail: section 16.

17. RECURRENCE/CHECKLIST ASSESSMENT
Lilica's existing Phase 8 recurrence engine already adequately serves
repeated caring responsibilities. No gap found; do not duplicate. Full
detail: section 17.

18. NOTIFICATION ASSESSMENT
Phase 14's reminder engine covers personal dated reminders well but has no
collaboration-notification concept (someone else's action affecting you).
Identified as dependent on the Recent Activity feed existing first, not
independent. Full detail: section 18.

19. SUPPORTED-PERSON INFORMATION ASSESSMENT
Jointly's DOB/condition/likes-dislikes profile fields are genuinely useful
but usefulness does not imply onboarding placement - Lilica's light
onboarding is a protected advantage. Recommend optional, post-onboarding
fields only, DOB still excluded, gated on legal/privacy classification for
health-adjacent fields. Full detail: section 19.

20. CARE CIRCLE/MEMBER-MANAGEMENT ASSESSMENT
Lilica already exceeds Jointly on security/permission granularity - a
genuine advantage. Narrower gaps found: no former-member list UI (data
exists per Phase 18B, unsurfaced), no cross-record member filtering, no
role-change UI (RPC exists, deferred by design). Full detail: section 20.

21. OFFLINE ASSESSMENT
Lilica's offline architecture is substantial; whether it represents parity
or advantage vs. Jointly's own current depth is genuinely uncertain from
available public sources. No gap identified; sync system not re-audited or
touched, per the brief's own instruction. Full detail: section 21.

22. EXPORT/HANDOVER ASSESSMENT
export_my_data() is technically complete but not human-optimised for an
emergency/handover moment. A distinct narrative summary view, built from
already-exported data, is identified as a natural sequel to the Recent
Activity and Contingency-summary candidates. Full detail: section 22.

23. ONE-YEAR-USER FINDINGS
Search and activity/history become the most acute difficulties; document
retrieval compounds without either; member activity becomes opaque exactly
as a circle grows. Full detail: section 23.

24. FAMILY-HANDOVER FINDINGS
Marion (David's stand-in) can determine what's happening soon, what needs
doing, and where documents/bills are - but cannot easily tell what has
already been done recently or what changed while she wasn't looking. A
real, meaningful gap directly corroborating the Recent Activity/Contingency
candidates. Full detail: section 24.

25. EMERGENCY-TEST FINDINGS
Lilica can provide whatever is already recorded, but only via manual
navigation and only to someone with prior Care Circle access - no fast
"what matters now" view exists. Recommendation is a curated summary for
someone who already has access, not a new access-control bypass or new
clinical data collection. Full detail: section 25.

26. SIX-PERSON COLLABORATION FINDINGS
Assignment/permission visibility already works well (a genuine strength);
nobody can easily tell what changed recently; historical contribution is
correctly retained but not surfaced as a coherent view. Full detail:
section 26.
